Deploy & setup guide

This single-file build contains the full product (public invite + secure admin + database layer). For production with a real server DB, promote the included Backend adapter to Postgres/Supabase in ~10 minutes.

1 — Folder structure (production)

for-val/
├─ public/
│  ├─ index.html        # this file (public invite)
│  └─ assets/
├─ server/
│  ├─ index.js          # express API + auth + validation
│  ├─ db.js             # pg / supabase client
│  ├─ auth.js           # bcrypt + JWT sessions
│  └─ validate.js       # shared Zod/Joi schema
├─ supabase/
│  └─ schema.sql        # table + RLS policies
├─ .env                 # DATABASE_URL, JWT_SECRET, ADMIN_HASH
└─ README.md

2 — Database schema (required fields)

create table responses (
  response_id text primary key,
  invitation_id text not null default 'inv_for-val_2026_01',
  accepted boolean not null,
  preferred_date text,
  preferred_time text,
  date_type text,
  preferred_location text,
  activity_preference text,
  food_restrictions text,
  likes text,
  dislikes text,
  comfort_preferences text,
  anything_else text,
  rapid_fire_answers jsonb default '{}',
  excitement_rating int check (excitement_rating between 1 and 10),
  submitted_at timestamptz default now(),
  updated_at timestamptz default now()
);
-- RLS: enable row level security;
-- allow INSERT from anon, SELECT/DELETE only for service_role (admin JWT).

3 — Server API (Node + Express sketch)

POST /api/responses      # public, rate-limited, validated, sanitized
GET  /api/responses      # admin JWT required
DELETE /api/responses/:id# admin JWT required
POST /api/admin/login    # bcrypt.compare → JWT (2h)
# Never expose ADMIN password or service key to client.

4 — Deploy

Vercel / Netlify (frontend): drag-drop this HTML file. Map /admin → /#/admin rewrite. Render / Fly (backend): deploy server/, set DATABASE_URL + JWT_SECRET. Paste the API URL into Settings → Cloud sync. Done.

Security checklist

✔ Server-side auth (JWT) • ✔ Input validation + length caps + HTML-escaping • ✔ Rate limit (5/min/IP) • ✔ RLS — public can only insert • ✔ Secrets in env, never in client • ✔ Admin session expiry + lockout • ✔ No private data on public routes.
